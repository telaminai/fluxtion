# FLX-1023

> No compiler sign-in found. Run `mvn com.telamin.fluxtion:fluxtion-maven-plugin:1.3.4:login` (or set FLUXTION_API_TOKEN for CI).

| | |
|---|---|
| **Severity** | ERROR |
| **Category** | GRAPH_MODEL |
| **Element** | `COMPILER_CALL` |

## The rule

A build that sends a compile request to the Fluxtion compiler must be signed in to a compiler account.

## Why the compiler says this

Generating this processor needs the Fluxtion compiler, and the compiler serves only signed-in builds: a credential from `mvn com.telamin.fluxtion:fluxtion-maven-plugin:1.3.4:login` (from any directory; `mvn fluxtion:login` inside a project that declares the plugin), or FLUXTION_API_TOKEN in CI. This build has neither, so it stops here, before anything is sent. The older RapidAPI key file is no longer read and is never used instead.

## How to fix it

Run `mvn com.telamin.fluxtion:fluxtion-maven-plugin:1.3.4:login` once on this machine and rebuild: Maven, Gradle, JBang and a plain `main` all find that sign-in. In CI, set FLUXTION_API_TOKEN to a credential created for the account (and FLUXTION_COMPILER_URL only if the account is on a compiler other than the managed one). A project that commits its generated processor and builds in ensure mode needs no sign-in while the compile request is unchanged.

## Which builds raise it

**A build that calls the Fluxtion compiler** (source generation, the model step, or the entitlement handshake) in the default, signed-in mode, with no compiler sign-in. It is raised before anything is sent. A build on the local generator route and a build in ensure mode whose compile request is unchanged need no sign-in and never raise it. In ensure mode a processor that must be regenerated without a sign-in raises `FLX-1022` instead, which names the processor and why it changed.

## Reading it programmatically

This diagnostic is also written to the machine-readable report — the opt-in sidecar (`-Dfluxtion.diagnostics.sidecar=true`), or `FluxtionDiagnostics.capture(...)` for a caller that wants the objects:

```json
{
  "code": "FLX-1023",
  "severity": "ERROR",
  "category": "GRAPH_MODEL",
  "element": { "kind": "COMPILER_CALL", … }
}
```

Select findings by `severity`, never by position: a failing build's report also contains any warnings it found, and `diagnostics[0]` is not the cause of the failure.
