# FLX-1024

> The Fluxtion compiler address in FLUXTION_COMPILER_URL is not usable: it must not carry user information (a credential or a second host before '@').

| | |
|---|---|
| **Severity** | ERROR |
| **Category** | GRAPH_MODEL |
| **Element** | `COMPILER_ADDRESS` |

## The rule

A compiler credential is sent only to a valid compiler address: https (plain http only to this machine), a host and optional port, with no user information, path, query or fragment; a path on the compiler starts with a single /.

## Why the compiler says this

This build is signed in and was about to send its credential to the compiler named by FLUXTION_COMPILER_URL. That address does not meet the rules a credential's destination must meet, so nothing is sent. A build that needs no compiler never reads the address, so it is not affected.

## How to fix it

Correct or remove FLUXTION_COMPILER_URL. With nothing set, a signed-in build uses the compiler that issued its stored sign-in, or the managed compiler https://compiler.fluxtion-playground.dev; FLUXTION_COMPILER_URL is for another compiler, written as its service root, for example https://compiler.example.com.

## Which builds raise it

**A signed-in build that is about to call the Fluxtion compiler**, when the setting that names the compiler (`fluxtion.remote.host`, `FLUXTION_COMPILER_URL`, the compiler recorded with a stored sign-in, `fluxtion.entitlement.url`, or a `/v1` path) is not usable. The address is read only at that point, so a build that needs no compiler (an ensure-mode reuse, a local generation) and a signed-out build (which raises `FLX-1023`) never raise it.

## Reading it programmatically

This diagnostic is also written to the machine-readable report — the opt-in sidecar (`-Dfluxtion.diagnostics.sidecar=true`), or `FluxtionDiagnostics.capture(...)` for a caller that wants the objects:

```json
{
  "code": "FLX-1024",
  "severity": "ERROR",
  "category": "GRAPH_MODEL",
  "element": { "kind": "COMPILER_ADDRESS", … }
}
```

Select findings by `severity`, never by position: a failing build's report also contains any warnings it found, and `diagnostics[0]` is not the cause of the failure.
