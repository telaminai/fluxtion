# FLX-1032

> no cpp mapping for node 'auditWindow' field 'openedAt' (java.time.Instant) — it was rendered for [rust]

| | |
|---|---|
| **Severity** | ERROR |
| **Category** | TARGET |
| **Element** | `FIELD` |

## The rule

A field serialiser renders for a named target; a rendering for one target is never reused for another.

## Why the compiler says this

Field serialisers are keyed by target language, and this field was rendered for [rust] but not for cpp. That rendering is the evidence that matters: serialisers WERE loaded where the capture ran, so this is a missing mapping and not a missing dependency — the classpath you would otherwise go and check is already correct. Fluxtion will not substitute another target's text, because source written for one language either fails to compile in another or, worse, compiles and means something else.

## How to fix it

Register a field serialiser for java.time.Instant whose target language is cpp, alongside the one you already have. It returns the member declaration for that target, naming the member from the field name the context carries — never an invented one, which compiles and then denotes a member the generated type does not have.

## Which builds raise it

**The target named in the message, on source-generating (AOT) builds only.** These are capability refusals, not modelling errors: the same graph generates for other targets, and an interpreted or in-process build never renders a target at all. Expect to meet one for the first time when you add a second target to a graph that has always built — that is the refusal doing its job, because the alternative is a processor that silently computes something different from its twin.
