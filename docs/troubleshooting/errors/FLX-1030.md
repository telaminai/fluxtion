## The rule

A target emits a graph in full or refuses it by name. It never emits a subset.

## Why the compiler says this

Fluxtion compiles ONE language-neutral model to whichever target you select, so a target's capability is separate from your graph's validity: this graph is sound and generates for other targets. What a target may not do is emit the part it understands and drop the rest — skipping this construct once produced a processor with no nodes at all, source that compiled cleanly and computed nothing. A refusal that names the construct is the only outcome that cannot be mistaken for success.

## How to fix it

Express this part of the graph with constructs the cpp target supports, or generate it for a target that carries this one. The capability matrix in the target's specification lists what is emitted today and what is refused.

## Which builds raise it

**The target named in the message, on source-generating (AOT) builds only.** These are capability refusals, not modelling errors: the same graph generates for other targets, and an interpreted or in-process build never renders a target at all. Expect to meet one for the first time when you add a second target to a graph that has always built — that is the refusal doing its job, because the alternative is a processor that silently computes something different from its twin.
